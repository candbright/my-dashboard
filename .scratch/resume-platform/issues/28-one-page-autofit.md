# 28 — 一页纸自动收缩 + 自动倒叙

- **Type**：task
- **Status**：ready-for-agent
- **Blocked by**：21（首套模板）、23（渲染服务，页数信息）、24（样式面板的旋钮）
- **Blocks**：—
- **ADR**：[ADR-0001](../../../docs/adr/0001-render-engine-selection.md)、[ADR-0004](../../../docs/adr/0004-presentation-state-in-jsonb.md)

## 背景

国内市场调研列出的"一键"能力，本项目**一个都没有**：

| 能力 | 竞品 |
|---|---|
| **一页纸自动收缩** | 简历本「自动缩成一页纸」；职徒「一键自动一页简历」 |
| **自动倒叙** | 按时间自动倒序排列经历 |
| **一键统一切换行距/页边距/颜色** | 职徒的四个"一键" |
| **一键切换日期格式** | 职徒 |

**"一页纸"在国内是硬需求**——应届生简历普遍要求单页。

## 任务

### 1. 一页纸自动收缩

**前置条件**：需要知道"排版后实际占几页"——这只有渲染服务知道（工单 23 的 `page_count` 告警）。这是本工单**依赖渲染服务**的原因。

- 调节旋钮（工单 24 已提供）：`fontScale`、`lineHeight`、`pageMargin`
- 算法：**迭代收缩**——从当前值开始，逐步降低 `fontScale` / `lineHeight`、增大可用区域，**每次重新渲染并检查 `page_count`**，直到 ≤ 1 页或触达下限
- **必须有下限**（如 `fontScale >= 0.85`、字号不小于可读阈值）——**不能为了塞进一页而把简历变成不可读**
- 触达下限仍超一页时：**明确告知用户超了多少**，并给出建议（删减内容 / 收紧某项），**不要静默失败**

### 2. 自动倒叙

- 按解析出的起止时间对条目**降序排列**
- 要点：
  - "至今"（`Present` / `至今`）视为**最大值**
  - 无日期的条目**保持原相对位置**（不要扔到末尾或开头）
  - 用户**手动拖拽排序后不再自动倒叙**（避免用户意图被覆盖）

### 3. 一键预设（工单 24 之上）

- **行距**：紧凑 / 标准 / 宽松
- **页边距**：窄 / 标准 / 宽
- **颜色**：几套合规色板（受 ADR-0004 约束：**冷色与纯黑被拒绝**）
- **日期格式**：`2022.03` / `2022年3月` / `2022/03` / `Mar 2022`

### 4. 全部通过展示态持久化

所有"一键"结果写入 `resumes.presentation`，**不产生内容版本历史**（ADR-0004）。

## 验收标准

- [ ] "自动缩成一页"能对超标简历生效，且**不把字号压到不可读**
- [ ] 无法压缩到一页时给出明确提示与具体超出量
- [ ] 自动倒叙正确，"至今"排最前，无日期条目不乱序
- [ ] 用户手动排序后不再被自动倒叙覆盖
- [ ] 四个预设（行距/边距/颜色/日期）均可用
- [ ] 所有变更写入展示态，**不产生内容版本历史**
- [ ] 收缩过程中每轮渲染有超时保护（不要无限迭代）
- [ ] 收缩后的输出通过工单 02 的 `assertPdfText`

## 备注

- ⚠️ **迭代收缩意味着多次渲染**——若渲染是同步阻塞的（Q31=A），一次"自动一页"可能发起多次渲染调用。**这是需要性能验证的点**；若过慢，考虑让渲染服务在一次调用内完成迭代。
- 一页纸收缩**只改样式，不改内容**。若必须删内容才能一页，那是用户的决定，不是产品的。
