# 38 — 分享链接保护与有效期

- **Type**：task
- **Status**：ready-for-agent
- **Blocked by**：11（迁移器）
- **Blocks**：37（SEO 必须与"不索引"联动）
- **ADR**：[ADR-0009](../../../docs/adr/0009-grants-authoritative-visibility-derived.md)

## 背景

公开简历页当前只有两个状态：`visibility`（private/public）+ `approval_status`（draft/approved）。

**缺失的分享控制**（调研中多个产品都有）：

| 能力 | 谁在做 |
|---|---|
| **密码保护分享** | Reactive Resume |
| **隐藏于搜索引擎（noindex）** | 多个产品的高级设置 |
| **自定义分享 URL** | VisualCV、Standard Resume |
| **分享链接有效期** | 部分产品 |

**"隐藏于搜索引擎"是一个常见的付费点**，但它本质上是**隐私承诺**——做不好就是欺骗。

## 任务

### 1. 新增分享设置（存储落点由本工单决定）

建议放**展示态 JSONB**（`presentation.sharing`，工单 19 的延伸）或**独立列**——本工单需明确选择并记录理由。

```jsonc
{
  "sharing": {
    "noindex": true,
    "password": null,          // 哈希后存储，绝不存明文
    "expiresAt": null,
    "customSlug": null
  }
}
```

### 2. 隐藏于搜索引擎（noindex）

- 公开页输出 `<meta name="robots" content="noindex, nofollow">`
- **必须同时从 sitemap 排除**（工单 37）
- ✅ **本工单与工单 37 有硬联动**——只做一半就是欺骗用户

### 3. 密码保护

- 密码**必须哈希存储**（bcrypt / argon2），**绝不存明文**
- 访问时校验，通过后签发一个短期访问凭据
- **不要用 slug 本身当密码**
- ⚠️ 密码保护的页面**必须同时 noindex**（搜索引擎不该看到需要密码的内容）

### 4. 有效期

- `expiresAt` 到期后公开页返回明确的"已过期"页面（而非 404 或空白）
- **owner 必须收到提醒**（到期前）——否则用户会不知道自己的简历已失效

### 5. 自定义分享 URL

⚠️ **与工单 13 的冲突**：ADR 与工单 13 决定 **slug 创建后不可变**。

- 若做自定义 URL，需要"旧 slug 重定向"机制，**不能静默让旧链接 404**
- 本工单可以**只做设置界面与后端字段，暂不实现改名**——但必须在 UI 上说明

### 6. 权限

- 修改分享设置需要 **owner 或 admin**
- 不新增权限类型（ADR-0009：`Known()` 是闭集校验）

## 验收标准

- [ ] noindex 生效：页面输出正确的 meta 标签
- [ ] noindex 的简历**不出现在 sitemap**（与工单 37 联动验证）
- [ ] 密码保护可用，密码**哈希存储**
- [ ] 密码保护的页面自动 noindex
- [ ] 有效期到期后显示明确的过期页面
- [ ] owner 在到期前收到提醒
- [ ] 分享设置的修改有权限控制
- [ ] 自定义 URL 的现状（slug 不可变）在 UI 中说明
- [ ] 有测试覆盖密码校验与过期逻辑

## 备注

- ⚠️ **"隐藏于搜索引擎"必须真的有效**。如果用户以为自己的简历不会被搜到，而实际仍被收录，这是**产品信任的严重损害**——比功能缺失严重得多。
- 访问统计（工单 36）与密码保护有交互：被密码拦截的访问**不应计入**浏览量。
