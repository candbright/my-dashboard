# 27 — 证件照工具

- **Type**：task
- **Status**：ready-for-agent
- **Blocked by**：19（展示态）、15（元数据面板）
- **Blocks**：—
- **ADR**：[ADR-0004](../../../docs/adr/0004-presentation-state-in-jsonb.md)

## 背景

**证件照（一寸照）是国内简历的一等公民**——超级简历把它作为会员权益单独售卖。

当前项目的照片能力**完全不可用**：

- `avatar` 只是一列 `varchar(500)` 存 URL
- `next.config.ts` 的 `images.remotePatterns` **只允许三个域**：`avatars.githubusercontent.com`、`lh3.googleusercontent.com`、`secure.gravatar.com`
- **用户上传的照片会被 CSP 与 `next/image` 一起挡掉**

已锁定的决策（Q27）：**复用 `avatar` 列 + 新增本地上传端点**；存储落点选**独立子目录**（Q32=B）。

## 任务

### 1. 后端：本地图片上传

- 新增上传端点（接受图片，校验类型与尺寸）
- 存储到**独立子目录**（如 `storage_dir/images/`），**不与 `{uuid}.md` 混放**
  > 理由：后端读取简历正文时用严格正则 `^[0-9a-f-]{36}\.md$` 做路径校验与目录穿越防护。往同一目录塞图片会让这条安全边界变模糊
- 沿用同样的存储模式：**磁盘文件 + 数据库只存路径**
- 路径存回 `resumes.avatar` 列
- **游客账户不可上传**

### 2. 前端：裁剪 + 换底色（纯客户端）

**换底色是前端 canvas 的活，不需要后端参与。**

- **裁剪**：固定比例（一寸照约 1:1.4），可拖动与缩放
- **换底色**：白 / 蓝 / 红（国内证件照三色）
  - 实现建议：色度键替换（对纯色背景生效）或引导用户先抠图
  - **不要假装能做智能抠图**——若不能可靠分离人像，就只做"背景色替换"并明确说明适用场景
- **尺寸预设**：一寸（25×35mm）、二寸（35×49mm）
- 产物为**处理后的图片**上传到后端

### 3. 与展示态的关系

证件照的**启用开关与位置**属于展示态（`presentation.photo`，工单 19）；**图片本体**属于元数据（`avatar` 列）。

### 4. 与 ATS 的关系

⚠️ **在模板的"解析友好度"标注中体现**：带照片的简历在国内是常态，但在部分国外 ATS 中照片区可能被解析为噪音。

- 在工单 22 的友好度判定标准中明确"含照片"的影响
- 照片**不得挤占文字**——单栏模板中照片应置于顶部角落，不与文字重叠

## 验收标准

- [ ] 可上传图片，路径存入 `avatar` 列
- [ ] 上传的图片能在展示页与 PDF 中正确显示（**不再被 CSP / remotePatterns 挡住**）
- [ ] 可裁剪为证件照比例，可选白/蓝/红底色
- [ ] 可选用一寸/二寸尺寸预设
- [ ] 图片存于独立子目录，**目录穿越防护未被削弱**
- [ ] 上传有类型与大小校验，错误为中文
- [ ] 游客账户不可上传
- [ ] PDF 中照片不遮挡文字
- [ ] 模板友好度标注已考虑照片因素

## 备注

- ⚠️ **`remotePatterns` 的处置**：既可以选择扩展白名单，也可以在渲染时用普通 `<img>` 绕开 `next/image`。**建议后者**——本地存储路径是"自己人"，不需要走远程图片优化管线；且改 `remotePatterns` 会放宽 CSP。
- 若将来支持 S3/对象存储，`avatar` 列的 URL 语义可以平滑扩展。
