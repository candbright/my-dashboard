# 35 — 附件简历邮件投递

- **Type**：task
- **Status**：ready-for-agent
- **Blocked by**：23（渲染服务）
- **Blocks**：—
- **ADR**：[ADR-0007](../../../docs/adr/0007-render-service-boundary.md)

## 背景

**「在线简历 vs 附件简历」是国内市场的核心机制**（市场调研 §2.2.1）：

- **在线简历**（`resume/[slug]` 页面）是 HR **最先看到**的，驱动搜索与匹配
- **附件简历**（PDF/DOCX）是**打印或转发给用人经理**的那一份

**用户对"HR 看到的是哪一份"长期困惑**，而调研结论是：**没有任何产品解决这个问题。**

对标：**简历本**支持把简历直接发送到 HR 邮箱。

## 任务

### 1. 产品核心：明确区分两种产物

**这是本工单最重要的部分。** 在 UI 上明确告知：

> 「你分享的**链接**是**在线简历**（HR 在网上看到的第一份）。
> **附件简历**是你下载或投递出去的文件。两者是**不同的东西**。」

- 提供一个显式的 **「生成附件简历」** 动作（而不是把导出埋在菜单里）
- 解释器要简短、放在**用户会看到的位置**，而不是帮助文档深处

### 2. 邮件投递

- 后端新增投递端点
- **需要 SMTP 配置**——`.env` / `config.yaml`，且**必须可选**（未配置时功能优雅禁用，而非报错）
- 邮件正文：简洁说明 + 附件
- 附件：渲染服务产出的 PDF（工单 23）
- **收件人地址校验**（防注入、防垃圾邮件滥用）
- **速率限制**——这是对外发信功能，必须有防滥用

### 3. 附件文件名的处理

中文文件名在邮件附件中容易乱码。方案：
- 使用 RFC 2231 编码
- 或提供 ASCII 回退名（如 `resume-zhangsan.pdf`）

## 验收标准

- [ ] UI 上明确区分"在线简历"与"附件简历"，且解释可见
- [ ] 有显式的「生成附件简历」入口
- [ ] 邮件可发送带 PDF 附件的简历
- [ ] SMTP 未配置时功能优雅禁用（明确提示，不报错）
- [ ] 收件人地址有校验
- [ ] **有速率限制**（防滥用）
- [ ] 中文附件名不乱码
- [ ] 游客账户不可投递
- [ ] 投递失败有中文错误提示
- [ ] 有测试覆盖地址校验与未配置 SMTP 的降级路径

## 备注

- ⚠️ **这是对外发信功能，安全面较大**：必须限速、必须校验地址、必须防止被当作开放中继。
- 待定项见 `spec.md` TD-5（生产部署的速率限制）——本工单的限速是最小必要实现。
- 与工单 38（分享链接保护）配合：一个管"发出去的文件"，一个管"分享出去的链接"。
