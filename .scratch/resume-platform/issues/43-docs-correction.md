## 背景

### 1. `kratos-server/AGENTS.md` 已过期

代码级审计确认以下错误：

| 文档声称 | 实际情况 |
|---|---|
| 无审批模块 | **存在** `internal/{biz,data,service}/approval` |
| `golang:1.19` | **`golang:1.26`** |
| `EXPOSE 8000` | **`EXPOSE 20002`** |
| AI 只是"通用 chat" | **有完整的 provider 网关、3 种协议、密钥加密、审批工作流** |

**过期的 Agent 文档比没有文档更糟**——它会主动误导后续工作。

### 2. `wire_gen.go` 是手工维护的

文件带 `// Code generated by Wire` 头，但**实际是手工维护的**（第 70–115 行有顺序注释）。这与依赖注入容器的常见预期不符，需要记录。

### 3. 安全基线缺口

| 缺口 | 风险 |
|---|---|
| **JWT secret 默认值**为 `"jwt-resume-vault-example"` | 生产部署若不改，**任何人的 token 都可被伪造** |
| **无速率限制**（登录 / 验证码 / AI 全是暴露面） | 暴力破解、验证码轰炸、API 费用滥用 |
| 种子账户 `admin/admin@example.com/admin` | 生产部署若未改密码，**直接是后门** |
| `AI_KEY_ENCRYPTION_SECRET` 未设置直接 panic | 行为正确，但需在部署文档中显著说明 |

> 注：`.env.example` 与 `DEPLOY.md` 可能存在，但需要核实是否覆盖以上各项。

## 任务

### 1. 订正 `kratos-server/AGENTS.md`

- 补上审批模块
- 修正 Go 版本、端口、AI 能力描述
- 补充：数据库 schema 由 `AutoMigrate` + **新的迁移器**（工单 11）共同管理
- 补充：简历正文是**磁盘 Markdown 文件**，数据库只存元数据
- 补充：`resume.proto` 路由与自定义 handler 的**注册顺序是有意的**（自定义 handler 必须先注册）
- 补充：JSON 大小写不一致（proto 路由 snake_case，自定义 handler camelCase；`bool` + `omitempty` 在 false 时消失——这是 `/api/admin/users` 用自定义 handler 的原因）

### 2. 记录 `wire_gen.go` 的真相

- 在文件头与 `AGENTS.md` 中明确：**此文件手工维护**
- 说明新增构造函数的接线顺序约定

### 3. 安全基线

- **启动时校验 JWT secret**：若为默认值，**生产模式拒绝启动**（开发模式警告）
- **种子账户**：文档中显著标注"生产部署必须修改"；考虑生产模式不创建默认密码
- **速率限制**：至少覆盖
  - 登录端点
  - 验证码发送（现有 60 秒节流不够）
  - AI 端点
- 核实并补全 `.env.example` 与 `DEPLOY.md`

### 4. 前端 `AGENTS.md` 补充

- 新增 `npm run test`（工单 01）
- 说明 `docs/adr/` 与 `CONTEXT.md` 的存在与用途
