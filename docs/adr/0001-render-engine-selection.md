# ADR-0001：渲染引擎选型

- **状态**：Accepted
- **日期**：2026-10
- **相关**：ADR-0002（前置 Spike）、ADR-0007（渲染服务边界）

## 背景

简历导出当前走 `html2canvas` + `jsPDF`：把 A4 页面光栅化成 PNG，再把 PNG 嵌进 PDF。

**该管线产出的 PDF 完全没有文字层**——ATS 拿到的是一张图片，不是文字。我方实测结论：这种文件在招聘系统里 **100% 解析失败**，比"双栏矢量 PDF"（已丢失 17.2% 内容）**严格更差**。

这是**正确性问题，不是优化问题**。修复它是所有导出相关功能的前置条件。

同时存在两个次级缺陷：同一个整页 `imgData` 在 `while` 循环里被反复 `addImage`（体积灾难）；分页按像素硬切，会把一条工作经历从中间劈开。

## 评估过的选项

| 选项 | 文字层 | 分页 | CJK | 基础设施 | tagged / PDF-UA | 结论 |
|---|---|---|---|---|---|---|
| 维持 html2canvas + jsPDF | ❌ 无 | ❌ 像素硬切 | 不适用 | 无 | ❌ | 必须替换 |
| **Forme**（`@formepdf/core`，Rust→WASM） | ✅ | ✅ 页原生 + Knuth-Plass + 孤寡行 | ✅ 可提取，但**内存不合格** | 无（Node/浏览器同引擎） | ✅ PDF/UA-1 | ❌ **Spike 否决**（判据 5） |
| **headless Chromium** | ✅ | ✅ | ✅ 由系统字体 + HarfBuzz 保证 | 容器 +300MB~1GB | ❌ **无法产出 tagged** | ✅ **终态引擎（阶段四）** |
| **Typst** | ✅ | ✅ 最强 | ✅ 最强（含 `cjk-latin-spacing`） | 需引入二进制 | ✅ PDF/UA-1 + PDF/A | 备选 |
| `@react-pdf/renderer` | ✅ | ✅ | ⚠️ 断行弱，需自建子集化 | 无 | ❌ | 备选 |
| 浏览器原生打印 + Paged.js | ✅ | ✅ | ✅ | 无 | ❌ | ✅ **阶段一止血（已实施）** |
| WeasyPrint | ✅ | ✅ | ✅ | 需 Python sidecar | ⚠️ | 备选 |

### 关键事实

- **位图 PDF 无文字层**是构造性的，非配置问题。
- **Paged.js 不产出 PDF**（最终仍走浏览器打印），因此**消除不了 Chromium 依赖**——这条推翻了初版"先用 Paged.js"的建议。
- **headless Chromium 无法产出 tagged PDF**，这是它相对 Forme/Typst 的实质劣势。
- **Forme 的 `@formepdf/html` 不支持 CSS 变量**，而本项目设计系统建立在 Tailwind v4 的 CSS 自定义属性之上——这点抵消了它"复用现有 CSS"的主要卖点。
- Forme 的 CJK 序列化性能缺陷（issue #182，韩文 5 页 **6,946 ms**）**仅在其 0.28.0 修复，发布距今数日**，且数据为厂商自报。
- 中文 PDF 的**可搜索/可复制性**取决于 `/ToUnicode` CMap，Forme 对此**无文档**，其 redaction 文档反而声明"CJK 无法被文本搜索找到"。

## 决策

**分两步走。ADR-0002 的 Spike 已执行完毕（2026-10-13），裁定结果见下。**

1. **阶段一：浏览器原生打印止血。** 用 `@page` + `break-inside: avoid` + 隐藏 iframe 拿到文字层。这是过渡实现，**不是终态**——它没有服务端能力，无法支撑邮件附件、批量导出、权威文件校验。**已实施**（工单 02–04）。
2. **阶段四终态：采用 headless Chromium。**
   - ~~若 Spike 通过 → 采用 Forme~~：**Spike 未通过**，见下。
   - **采用 headless Chromium**：现有 `ResumePrintView` 几乎原样复用、CJK 由成熟字体栈保证、风险最低。代价：接受无 tagged PDF 与更重的容器。

### ADR-0002 Spike 裁定（2026-10-13）

Forme 的**中文提取能力本身合格**——判据 1（逐字正确）、4（P95 860 ms）、6（0.468 MB，子集化生效）、7（0 条告警）、8（Next 16.2.6 + Turbopack 构建成功）全部通过。

**但判据 5 失败，且是硬失败：峰值内存 1,521.8 MB，上限 512 MB。** 关键证据是这一开销**与文档规模、用字数量都无关**：一份 342 字节、17 个不同汉字的文档首次渲染即占用 578.9 MB；且进程 RSS **不回落到基线**，随渲染次数单调上升（12 次渲染后峰值 1,521.8 MB）。对 ADR-0007 描述的常驻渲染单元，这意味着内存不收敛。

因此按 ADR-0002 预注册的判定规则（"任一 FAIL → Chromium"）选择 **headless Chromium**。完整测量、复现命令与两个附带缺陷见 [ADR-0002](./0002-cjk-render-spike.md) 的「Spike 结果」一节与 `.scratch/resume-platform/fixtures/RESULTS.md`。

> 附带发现（不改变判定，但影响任何渲染实现）：Forme 会把 `<html>`/`:root` 上的 `font-family` **静默忽略**（`<body>` 被当作独立布局根），导致这类模板产出整篇 `?` 的 PDF 且无告警；其 HTML 路径与 React 路径的字体参数形状不同，传错时静默丢弃字体数据。若将来重新评估 Forme，这两点必须先复测。

**无论选哪条，两项强制要求：**

- **`assertPdfText` 断言**：导出后立即用 `pdfjs-dist` 抽取文字，若为空或含替换字符（`�`/`?`）则**拒绝交付该文件**。移植自 Reactive Resume，约 50 行。这是把"我们认为 ATS 安全"变成可执行测试的唯一机制。
- **CJK 字体必须按文档子集化**，且**必须自带并显式注册中文字体**（`debian:bookworm-slim` 无中文字体，Fontconfig 匹配有静默降级风险）。Spike 实测 Windows 自带 `simhei.ttf` 覆盖 ADR-0002 fixture 的全部 2,271 个不同汉字（0 条缺字告警），可作为自带字体候选。

## 后果

**正面**
- 附件简历首次成为机器可读的文件，ATS 体检（ADR-0005）才有存在意义。
- 分页、孤寡行、页眉重复等排版能力一步到位。
- 引擎选择已由预注册的 Spike 裁定，不再有悬置的不确定性。

**负面 / 代价**
- 渲染服务引入新的部署单元（ADR-0007）。
- 走 Chromium 路线：容器显著变大、无 tagged PDF。
- ~~若走 Forme 路线：引入一个 pre-1.0、单维护者的依赖~~ —— **该风险未被接受**，因为 Forme 分支未被选中。
- 中文可提取性不再是"建立在一次 Spike 之上"的假设：ADR-0002 的测试文档已固化为常驻回归用例（`.scratch/resume-platform/fixtures/`），"中文可提取"由此被持续验证。

**被否决的方向与原因**
- **维持位图导出**：不可接受，见背景。
- **Paged.js 作为主方案**：不产出 PDF，消除不了浏览器依赖。
- **Typst 作为首选**：排版最优，但要维护第二套模板；且浏览器侧 `typst.ts` 的 PDF 导出**无法核实**（README 只演示 SVG 输出），因此只能走服务端二进制，成本高于收益。保留为备选。
