# ADR-0007：渲染服务边界与契约

- **状态**：Accepted
- **日期**：2026-10
- **相关**：ADR-0001（引擎选型）、ADR-0005（ATS 体检）、CONTEXT.md §3

## 背景

产出附件简历的能力当前**散落在前端**：`usePdfExport.tsx` 自己创建离屏容器、`createRoot` 渲染、`html2canvas` 截图、`jsPDF` 组装。渲染逻辑、分页策略、导出格式与 UI 组件纠缠在一起。

ADR-0001 决定引入服务端渲染。随之而来的问题是：**渲染放在哪里、对谁暴露什么、第一次交付多少。**

同时 ADR-0005 需要"关于产出文件本身的事实"（字体是否缺失、是否有字符被丢弃、文字层是否为空），而这些事实**只有渲染方知道**。

## 决策

### 1. 渲染收敛为单一接口

**`RenderService` 是唯一知道如何把结构化内容变成文件的组件。**

```
RenderResume(结构化内容, 展示态) → (文件字节, 渲染告警[])
```

- **输入**：ADR-0003 的`结构化内容` + ADR-0004 的`展示态`
- **输出**：文件字节 **与** `warnings[]`（ADR-0005 的数据源）

**这个接口是硬边界**：调用方不得知道引擎是 WASM、Chromium 还是 Typst。

### 2. 部署形态：阶段一内联，阶段四独立

| 阶段 | 形态 |
|---|---|
| **阶段一** | **浏览器原生打印**充当实现——`@page` + `break-inside: avoid` + 隐藏 iframe。纯前端，零基础设施，**只为拿到文字层止血** |
| **阶段四** | 替换为**独立渲染服务**（独立部署单元） |

**阶段一不做独立服务。** 理由：你还没有需要排队或隔离的规模，现在引入第二个部署单元是过早优化；**但接口必须先定好**，否则阶段四会变成考古。

### 3. 渲染告警的内容

| 告警 | 用途 |
|---|---|
| `text_layer_empty` | `assertPdfText` 失败信号 |
| `font_missing` | 字体未嵌入 |
| `chars_dropped` | 字符被渲染为 `?` 或 `�` |
| `page_count` | 一页纸约束（阶段四） |
| `cjk_char_count` | 验证子集化是否生效 |

**它们描述的是"产出文件里有什么"，不是"内容写得好不好"**——后者是 AI 诊断的职责（ADR-0005 边界）。

### 4. 内部鉴权

渲染服务**只接受内部调用**（共享密钥或内网），不对外暴露。它不是公开 API。

### 5. `assertPdfText` 的归属

断言在**渲染服务内部**执行：导出后立即抽取文字，为空或含替换字符则**拒绝交付该文件**（抛错，而非返回坏文件）。

约 50 行（移植自 Reactive Resume）。**这是把"我们认为 ATS 安全"变成可执行测试的唯一机制。**

## 后果

**正面**
- 渲染与简历领域解耦，可独立伸缩与崩溃隔离。
- 引擎可替换（ADR-0002 的 Spike 结果不影响调用方）。
- ATS 体检（ADR-0005）获得天然且可信的数据源。
- `assertPdfText` 有了明确归属地，且**作用于所有导出路径**——不可能绕过。

**负面 / 代价**
- 阶段四新增一个部署单元与一份内部鉴权约定。
- **同步接口**（Q31=A）：大批量导出会阻塞调用方。接受，因为尚无此规模；**异步与队列推迟到真正痛了再加**。
- 渲染服务需要自己的字体文件（ADR-0001 要求自带并显式注册中文字体）与容器镜像。
- 阶段一与阶段四的**实现不同、契约相同**——期间存在"接口已定但实现是临时的"状态，须在代码注释中显式标注，避免后人误以为浏览器打印是终态。

**明确不做**
- 异步任务 / 回调 / 结果缓存（Q31 已定：推迟）
- 作业跟踪（TD-3 排除清单）
- 对外暴露的公开渲染 API
