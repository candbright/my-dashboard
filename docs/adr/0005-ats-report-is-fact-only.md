# ADR-0005：ATS 体检只报事实，不报分数

- **状态**：Accepted
- **日期**：2026-10
- **相关**：ADR-0001（渲染）、ADR-0007（渲染告警）

## 背景

「ATS 体检」是本项目**唯一无人占据的差异化位置**（市场调研 §4.2 排名第 1、第 5）。

行业里已有的两种做法，**都推出了不应模仿的东西**：

| 做法 | 代表 | 问题 |
|---|---|---|
| 只诊断**内容质量**，不看产出文件 | Resume Worded | 被批评"只评分内容、不开导出文件"——它无法知道你的 PDF 到底能不能被读 |
| 给**不透明分数**，波动不可解释 | MyPerfectResume | **把一个社交链接区块改名为 "Websites"，分数从 89 掉到 70。** 这是升级诱导，不是诊断 |

同时存在一个**结构性事实**：由 ADR-0001，本项目此前的产出文件**没有文字层**。任何在这个状态下发布的"ATS 分数"都是**建立在不存在的文字层之上的**。

## 决策

**ATS 体检是一个"解析可读性报告"，不是分数。**

### 一级 UI 是「提取文本」

界面主体展示**招聘系统解析器实际读到的内容**——从产出文件中抽出的纯文本，逐段呈现。

用户看到的是**事实**：它读到了什么、漏了什么。这不可能被质疑。

### 二级是文件级风险清单

按严重度排序，**每条标注来源规则**：

| 风险 | 判定依据 |
|---|---|
| 无文字层 | 抽取文本为空（`assertPdfText` 失败） |
| 存在分栏 | 文本行聚类后检测到栏间空白（直方图） |
| 联系方式落在页边距区域 | 文本元素坐标位于页边距框内 |
| 技能被图标化/图片化 | 该区域无文本但有图像对象 |
| 字符渲染失败 | 抽取文本含 `�` 或 `?` |
| 字体未嵌入 | 读取 PDF 字体引用发现缺失 |

> 数值参考：行业数据集显示双栏导致 **17.2%** 内容丢失、装饰性图标 **10.6%**、联系方式置于页眉 **4.1%**。

### 严格边界

1. **只使用"实际抽取到的文本"作为信号。** 不引入任何需要判断"写得好不好"的规则。
2. **不给出内容质量评分。** 那是 `analyze` AI 能力的职责，**与卫生检查严格分离**（术语见 `CONTEXT.md` §4）。
3. **若将来引入数字分数**，必须满足三个条件：① 完全由提取文本信号计算；② 每条可溯源到具体规则；③ **我们能为它的每一次波动逐行辩护**。不满足则不发布。

### 数据来源

风险清单的数据来自 `RenderService` 返回的**渲染告警**（ADR-0007）——渲染服务本就在处理"结构化内容 → 文件"，让它同时报告"字体是否缺失、是否有字符被丢、实际页数、中文字符数"几乎是免费的。

## 后果

**正面**
- **报告不可能被质疑**——它陈述的是文件里存在什么，不是意见。
- 直接对标国内头部在宣传的 "ATS 系统兼容性校准"，但基底更硬（基于产出文件，而非内容特征）。
- 与 `assertPdfText` 共用同一条抽取链路，实现成本低。
- 为将来的 AI 诊断留出了干净的接口：解析可读性（事实）+ 内容质量（意见）两个独立层。

**负面 / 代价**
- **没有"分数"这个高传播性的钩子。** 国内用户习惯看到一个数字。缓解：提供可解释的"问题计数"与严重度分级，但**不合成单一分数**。
- 需要真实的 PDF 文件级分析能力（文本抽取 + 版式推理），不是简单的内容正则。实现量高于"给个分数"。
- 分析依赖渲染服务的告警输出，因此**排在 ADR-0001/0007 之后**。

**被否决的方向**
- **发布合成分数**：MyPerfectResume 的先例证明它会被用来做升级诱导，且一旦发布就背上辩护义务。
- **混合内容质量与解析可读性**：会让报告失去"不可辩驳"这一唯一优势。
